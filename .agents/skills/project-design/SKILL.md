# Project design

Before making UI or visual decisions, read `DESIGN.md` at the repository root and use it as the source of truth for colors, typography, spacing, radii, components, layout, imagery, responsive behavior, and accessibility.

Preserve the product's existing behavior and content requirements. When the requested design conflicts with `DESIGN.md`, follow the user's explicit request and keep the rest of the design system consistent.

Reuse existing project components and tokens where they already express the design system. When implementation details are missing from `DESIGN.md`, infer the smallest consistent extension from its established patterns.

After implementation, verify the affected UI at relevant viewport sizes and check readable contrast, keyboard focus, and reduced-motion behavior where applicable.
